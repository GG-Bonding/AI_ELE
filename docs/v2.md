# V2 — Experience Intelligence

V1 solved runtime experience learning:

```text
Experience can be produced → used → feedback received → utility changed
```

V2 solves harder questions:

```text
Which experience caused success/failure?
What if experiences conflict?
Can duplicates merge?
Can concrete experiences become Patterns/Skills?
```

| Version | Focus |

V2 pillars:

```text
Attribution + Conflict + Generalization + Evolution
```

## V2-4 Semantic Dedup (landed)

Two-stage store path:

1. **Exact** — within-episode `fingerprint` / `dedup_key` (unchanged)
2. **Semantic** — after embed, search same tenant/type/scope/(scope_key) neighbors; if cosine > 0.92, `DedupJudge` → `SAME` / `RELATED` / `DIFFERENT` / `CONFLICT`

| Decision | Store behavior |
| --- | --- |
| `SAME` | **Reinforce** existing row: merge `support_episode_ids`, raise **Confidence**; **do not** INSERT; **do not** change Utility |
| `RELATED` / `DIFFERENT` | INSERT new experience |
| `CONFLICT` | Do not merge (full conflict engine is V2-5); INSERT if no SAME neighbor |

Default judge: deterministic `HeuristicDedupJudge` (polarity + lexical overlap + auto-same ≈ 0.97). LLM judge can plug in later via `DedupJudge`.

API: complete-outcome / learning responses may include `reinforced_experiences` alongside `stored_experiences`.

## V2 Definition of Done (target)

1. Precise attribution — correcting one action only adjusts related experiences
2. Semantic dedup — same meaning merges evidence, not ACTIVE duplicates
3. Conflict — opposing experiences are not blindly injected into context
4. Generalization — ≥3 independent episodes can yield a Pattern with DERIVED_FROM
5. Pattern learning — Pattern utility moves with feedback
6. Benchmark — lower negative transfer and higher success vs V1 utility-only

Do not start V3 (auto-executed Skills) until V2 DoD is met.
